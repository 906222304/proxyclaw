# 项目优化检查（2026-10-08）

本次检查覆盖界面加载、周期刷新、进程树后台推送、图标缓存及 DNS 启动流程。之前的高清屏适配修改继续保留。

## 已实现

| 问题 | 修改 | 验证方式 |
| --- | --- | --- |
| 打开设置就下载整个 Monaco 编辑器 | 将编辑器、中文语言包和 Worker 配置拆到 `frontend/src/lib/monacoRuntime.ts`，点击“编辑”时才加载 | 生产构建资源大小及浏览器请求记录 |
| 关闭编辑器只释放视图，文本模型持续保留 | 同时释放视图和模型，加载期间关闭或离开页面时阻止迟到的初始化 | 浏览器反复开关，检查模型数量从 1 回到 0 |
| 慢接口使周期请求重叠，切换进程后旧结果覆盖新结果 | 状态、网络连接、进程活跃状态统一使用 `asyncPoller`；完成后再计时，支持取消及结果版本校验 | 控制请求完成顺序的 5 项异步测试 |
| 隐藏后恢复窗口没有主动同步进程树 | 恢复时在后台串行队列重新生成并推送当前数据；初始化时同步真实可见状态 | 独立进程树推送测试 |
| 合并推送计时器已取消的旧回调可能清除新任务的状态 | 先检查取消结果，再修改合并状态；隐藏时不执行已排队的刷新 | 取消、重新排队、后续事件的计时回归 |
| 每个 UDP 数据包在默认日志级别写入发送/上行/下行日志 | 正常逐包记录改成 Debug，保留会话建立及异常日志；正常发送不再额外查询本地套接字地址 | 原生编译与 DNS 真实网络回归 |

设置页 JS 从原来的 **3,788,720 字节**变为约 **14.8KB**。约 **3.76MB** 的编辑器仍随程序打包，但延迟到使用时加载；这不是整个程序体积降低，也不是 CPU 或内存实测下降百分比。

快速关闭时，编辑器的后台符号搜索产生了未处理取消异常。JSON 配置编辑器关闭该搜索，保留 JSON 语法、补全和校验。

## 后续值得做

1. **DNS 启动的界面等待进一步异步化。** 2026-10-09 已将底层 UDP 握手改成异步操作并增加 10 秒总期限，生产 UDP 转发不阻塞网络线程；DNS 启动接口仍同步等待独立 IO 完成，因此启用 DNS 的调用最多可能等待这个期限。连接稳定性修复和验证见 `CONNECTION_STABILITY_REVIEW.md`。
2. **支持仅 TCP 的 DNS 启动模式。** 当前 DNS 转发器启动必须先建立 UDP ASSOCIATE；不支持 UDP 的代理会使启动失败，虽然运行中的查询已经支持 TCP 回退。应先验证 TCP 隧道可用，再考虑启用该模式，并保留系统 DNS 的备份和恢复保障。
3. **改进图标缓存。** 目前按路径的 PNG 缓存和按名称的映射没有容量上限；相同文件名、不同路径的程序可能复用错误图标。失败查找写入空路径后，下一次仍会重复枚举进程。适合改成路径优先、失败查找带重试期限，并调整返回值所有权后再做容量限制。
4. **进一步拆分主界面资源。** 主界面脚本约 1.48MB，表格模块可继续按页面或功能拆分。应以启动时间和切换页面时间测量为依据，避免仅拆文件却增加初始化开销。
